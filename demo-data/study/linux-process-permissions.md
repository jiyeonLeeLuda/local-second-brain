# 리눅스 프로세스와 권한

맥미니를 화면 없는 서버로 쓰려면 터미널로 프로세스를 살피고 권한 문제를 해결할 줄 알아야 한다. macOS도 유닉스 계열이라 대부분 그대로 통하고, 컨테이너 안은 리눅스라 더 중요하다.

## 프로세스 기본

### PID와 부모 프로세스

모든 프로세스는 PID를 갖고, 자신을 만든 부모 프로세스(PPID)가 있다. 컨테이너 안에서는 실행한 명령이 PID 1이 된다.

```bash
ps aux | grep uvicorn
top            # 또는 htop
lsof -i :8000  # 8000 포트를 쓰는 프로세스 찾기
```

"포트가 이미 사용 중" 에러가 나면 `lsof -i :포트`로 범인을 찾는다. 프론트엔드 개발 서버가 3000번에서 안 꺼졌을 때 자주 썼던 명령이다.

### 시그널

- `SIGTERM`(15): 정상 종료 요청. 프로세스가 정리 작업을 할 수 있다.
- `SIGKILL`(9): 강제 종료. 거부할 수 없고 정리도 못 한다.
- `SIGINT`(2): 터미널에서 Ctrl+C.

`kill PID`는 기본이 SIGTERM이다. `kill -9`는 최후의 수단이다.

### 컨테이너의 PID 1 문제

헷갈렸던 점: `docker stop`은 PID 1에 SIGTERM을 보내고, 10초 안에 안 끝나면 SIGKILL을 보낸다. 그런데 Dockerfile에서 `CMD uvicorn ...`처럼 셸 형식으로 쓰면 셸이 PID 1이 되고, 셸이 시그널을 자식에게 전달하지 않아 매번 10초 기다린 뒤 강제 종료된다. `CMD ["uvicorn", ...]` 처럼 exec 형식으로 써야 한다. 작업 중인 워커가 정상 종료되지 못하면 작업이 중간에 끊기니 중요하다.

## 파일 권한

### rwx와 숫자 표기

`ls -l` 결과의 `-rw-r--r--`는 소유자, 그룹, 기타 사용자 순으로 읽기(r=4), 쓰기(w=2), 실행(x=1) 권한을 나타낸다.

```bash
chmod 644 notes.md      # 소유자 rw, 나머지 r
chmod 600 .env          # 소유자만 읽기/쓰기
chmod +x deploy.sh      # 실행 권한 추가
chown user:group file
```

`.env`나 SSH 개인 키는 `600`으로 둔다. SSH는 개인 키 권한이 너무 열려 있으면 아예 사용을 거부한다.

### 디렉터리의 x 권한

디렉터리에서 `x`는 "실행"이 아니라 "안으로 들어갈 수 있음"을 뜻한다. `r`만 있고 `x`가 없으면 목록은 보이는데 파일을 열 수 없다. 처음엔 이해가 안 됐던 부분이다.

## 컨테이너와 사용자

### root로 돌리지 않기

컨테이너는 기본적으로 root로 실행된다. 앱에 취약점이 있으면 공격자가 컨테이너 안의 root 권한을 얻는다. Dockerfile에서 일반 사용자를 만들어 전환한다.

```dockerfile
RUN useradd -m app
USER app
```

### bind mount 권한 충돌

호스트 폴더를 마운트하면 파일의 UID가 그대로 보인다. 컨테이너 사용자 UID와 호스트 파일 소유자 UID가 다르면 쓰기 권한 오류가 난다. 노트 폴더는 어차피 읽기 전용(`:ro`)으로 마운트할 계획이라 읽기 권한만 맞으면 된다.

## 환경변수와 PATH

`command not found`의 대부분은 PATH 문제다. `which python`, `echo $PATH`로 확인한다. 셸 설정 파일(`.zshrc`)에서 넣은 값은 SSH 비대화형 접속이나 launchd에서 실행할 때 적용되지 않을 수 있다. 원격으로 스크립트를 돌릴 때 주의할 점이다.

## 정리

- 종료는 SIGTERM 먼저, 컨테이너 CMD는 exec 형식.
- 비밀 파일은 600, 컨테이너는 non-root.
- 권한 오류가 나면 UID와 마운트 옵션부터 본다.
