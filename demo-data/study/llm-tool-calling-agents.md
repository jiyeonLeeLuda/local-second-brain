# LLM 도구 호출과 에이전트

LLM은 텍스트만 만들 수 있다. 그런데 "내 노트에서 찾아봐", "오늘 날짜 알려 줘" 같은 일을 하려면 외부 기능을 써야 한다. 그 연결 고리가 도구 호출(tool calling, function calling)이고, 이걸 반복하는 구조가 에이전트다.

## 도구 호출의 동작 방식

### 모델은 함수를 실행하지 않는다

가장 크게 오해했던 부분이다. 모델은 "이 함수를 이 인자로 불러 줘"라는 **요청을 JSON으로 출력**할 뿐이고, 실제 실행은 내 코드가 한다.

1. 요청에 사용 가능한 도구 목록(이름, 설명, 파라미터 JSON Schema)을 함께 보낸다.
2. 모델이 도구가 필요하다고 판단하면 `tool_calls`를 담은 응답을 돌려준다.
3. 내 코드가 해당 함수를 실행한다.
4. 결과를 `role: "tool"` 메시지로 대화에 추가해서 다시 모델을 부른다.
5. 모델이 결과를 보고 최종 답을 만들거나 또 다른 도구를 부른다.

```python
tools = [{
    "type": "function",
    "function": {
        "name": "search_notes",
        "description": "사용자의 스터디 노트에서 관련 구절을 검색한다",
        "parameters": {
            "type": "object",
            "properties": {
                "query": {"type": "string"},
                "top_k": {"type": "integer", "default": 5}
            },
            "required": ["query"]
        }
    }
}]
```

### 도구 설명이 곧 프롬프트다

모델은 `description`을 읽고 언제 도구를 쓸지 결정한다. 설명이 모호하면 엉뚱한 때 부르거나 안 부른다. 파라미터 스키마는 Pydantic 모델에서 `model_json_schema()`로 만들면 검증까지 한 번에 처리된다.

## 에이전트 루프

에이전트는 결국 아래 반복문이다.

```python
while True:
    resp = llm(messages, tools=tools)
    if not resp.tool_calls:
        return resp.content
    for call in resp.tool_calls:
        result = run_tool(call.name, call.arguments)
        messages.append({"role": "tool", "tool_call_id": call.id, "content": result})
```

### 꼭 필요한 안전장치

- 최대 반복 횟수: 모델이 같은 도구를 무한히 부르는 경우가 있다.
- 인자 검증: 모델이 만든 인자는 사용자 입력처럼 신뢰하지 않는다.
- 권한 분리: 읽기 도구와 쓰기/삭제 도구를 나누고, 위험한 도구는 사람 승인을 거친다.
- 비용과 시간 제한: 로컬 모델이라도 한 작업이 몇십 분씩 돌면 곤란하다.

헷갈렸던 점: "에이전트"라고 하면 거창한 시스템을 떠올렸는데, 핵심은 반복문과 도구 실행기, 그리고 멈추는 조건이다. 이걸 감싸서 파일 시스템, 권한, 기록 관리까지 제공하는 실행 환경을 하네스(harness)라고 부른다.

## 작은 로컬 모델과 도구 호출

8B급 모델은 도구가 많으면 잘못 고르거나 JSON 인자를 틀리게 만드는 경우가 늘어난다.

- 도구 수를 적게 유지한다(5개 이내부터 시작).
- 도구 이름과 설명을 서로 확실히 구분되게 쓴다.
- 서버가 도구 호출 형식을 지원하는지(채팅 템플릿) 확인한다. 지원하지 않으면 JSON 출력을 직접 파싱해야 한다.

## 워크플로와 에이전트의 구분

모든 걸 에이전트로 만들 필요는 없다. 단계가 정해진 일(검색 → 생성)은 코드로 순서를 고정한 워크플로가 더 빠르고 예측 가능하다. 에이전트는 어떤 단계가 몇 번 필요할지 미리 알 수 없는 일(예: "이 주제를 내 노트에서 조사해서 정리해 둬")에 쓴다. 이렇게 오래 걸리는 에이전트 작업은 백그라운드 작업 큐로 돌리는 게 맞다.
