## 0. 이 문서의 용도

- 개인 프로젝트의 타당성, 기술 선택, 보안 설계, 실험 설계, 이직 포트폴리오 가치를 다른 AI에게 교차 검증받기 위한 문서입니다.
- 검증자는 "현실적인가, 빠진 것은 없는가, 더 나은 대안은 없는가, 채용 관점에서 가치가 있는가"를 비판적으로 평가해 주세요. 동의보다 반론이 더 유용합니다.

## 1. 배경

- 작성자: 미술 전공, 현재 프론트엔드 개발자. 풀스택(백엔드와 AI 이해)으로 이직을 준비 중입니다.
- 성향: 루틴 유지가 어렵습니다(ENFP). 스트릭, 재촉, 의무감을 만드는 구조는 피해야 합니다. 의지가 아니라 시스템과 흥미로 지속되어야 합니다.
- 동기: 기술은 "내 삶에 쓸모가 있을 때" 배울 의욕이 생깁니다. 실제로 매일 쓰고 싶은 도구를 만들면서 백엔드, AI, 에이전트 기술을 이해하는 것이 목적입니다.
- 이직 포트폴리오로서의 가치가 핵심 평가 지표 중 하나입니다.

## 2. 비전과 검증 가능한 주장

- **비전**: 감정과 직관에 논리를 보충해주고, 두서없이 쏟아낸 문장들 속에서 인사이트를 얻고자 이 도구를 개발하게 되었다. 모닝페이지라는 도구를 디지털 데이터로 옮겨와 키워드들간의 연결을 통해 새로운 영감, 창의성을 발견할 수 있는 시스템을 구축하고자 한다. 결과적으로 사용자는 이 시스템을 통해 창조성을 회복하고 생생활활한 삶을 살아갈 동기를 부여하며 스스로를 성찰하는 시간을 만들 수 있다.
- **검증 가능한 주장(탐색적)**: 기록 사이의 연결을 되돌려 보여주는 방식에 따라 어떤 종류의 성찰과 영감이 일어나는가. 특히 무작위 연결을 포함한 여러 연결 방식이 각각 어떤 가치를 만드는가.
- **설계 원칙**
  1. 동기부여는 AI가 생성한 격려 문구가 아니라 "과거의 내 문장을 되돌려주는 것"으로 만든다.
  2. 쓰는 동안 AI는 개입하지 않는다.
  3. 성찰을 재촉하지 않는다. 열었을 때만 새로운 것이 있다.
  4. 원본은 언제나 내가 쓴 MD 파일이다.

## 3. 제품 구조: 공통 엔진 + 모드

**공통 엔진**: 가져오기 → 청킹 → 임베딩 → 저장(Postgres + pgvector) → 검색 → (필요 시) LLM 호출

**모드**
- **모드 1. 오늘의 연결**: 일기, 메모, 스터디 노트 사이의 뜻밖의 연결을 보여주는 실험적 핵심 기능
- **모드 2. 스터디 Q&A**: 스터디 노트와 영어 기술 문서에 질문하고 출처와 함께 답을 받는 정통 RAG
- **모드 3. 면접 코치**: 이력서, 채용공고(JD), 스터디 노트를 바탕으로 예상 질문, 꼬리질문, 답변 피드백. 일기는 검색 대상에서 제외
- **모드 4. 영어 기술 문서 독해 보조**: 영어 원문은 보존하고 한국어 설명을 덧붙임. 막힌 문장 풀이(구조와 핵심 표현 설명), 내 용어집 자동 수집, 선택적 복습
- **부가 기능. 노트 내 조사 작업**: "이 주제를 내 노트에서 조사해서 정리해 둬"를 백그라운드 작업으로 실행하고 결과를 inbox에 저장

## 4. 목표와 비목표

**목표**
- 모드 2와 3을 완성도 있게 동작시키고, 모드 1은 실험과 평가 결과까지 문서화합니다.

**비목표**

- 웹을 읽는 자율 에이전트와 개인 데이터의 결합

## 5. 환경과 제약

- 하드웨어: Mac mini M4, 통합 메모리 24GB
- 로컬 모델(사용 중): Qwen3.5-9B-GGUF(메인 생성, 구조화 추출). 추론(thinking)은 `chat_template_kwargs`로 끔(ADR 0004). 초안의 후보였던 Qwen3 8B, Gemma 3 4B는 설치하지 않음
- 추론 서버: Lemonade 2026.45.3(맥미니). OpenAI 호환 경로(`/api/v1`)와 임베딩 엔드포인트 확인 완료. LLM은 한 번에 1개만 로드되고 다른 모델 요청 시 교체됨, 임베딩 슬롯은 별도
- 대안 서버: llama.cpp의 llama-server(`--embedding`), Ollama, LM Studio
- 임베딩 모델(사용 중): Qwen3-Embedding-0.6B-GGUF(1024차원). 검색 질문에만 지시문을 붙임(ADR 0007). 초안의 후보였던 bge-m3는 쓰지 않음
- 백엔드: FastAPI(Python) / 프론트엔드: Next.js(TypeScript) / 컨테이너: Docker(OrbStack)
- 원격 접속: 인바운드 포트를 열지 않고 Tailscale 사용

### 5-1. 개발·운영 환경 분리

- **맥북 = 개발 환경**: 오르카로 코딩. demo-data와 개발용 Postgres(Docker)로만 테스트
- **맥미니 = 운영 서버**: 화면 없이 상시 가동. 실제 개인 기록(비공개 볼트, 별도 비공개 레포로 동기화. `.env`의 `HOST_NOTES_DIR`를 컨테이너 `/notes`에 읽기 전용으로 마운트하고, 소스별 폴더는 `SOURCE_DIRS`로 `NOTES_DIR` 기준 상대 경로 또는 절대 경로로 지정), 운영용 Postgres, Lemonade(LLM·임베딩 서버) 실행
- **코드 이동**: 맥북에서 `git push` → 맥미니에서 `git pull` 후 `docker compose up -d --build`. 처음엔 `deploy.sh` 한 줄 스크립트로 시작하고, 자동 배포(GitHub Actions)는 나중에 선택
- **모델 호출**: 맥북 개발 중에도 LLM과 임베딩은 맥미니 Lemonade를 Tailscale 주소로 호출. `LLM_BASE_URL`, `EMBED_BASE_URL` 환경변수로 기기별 주소만 다르게 설정
- **DB 스키마 동기화**: 맥북·맥미니 DB는 분리하고 마이그레이션 도구(Alembic)로 구조만 맞춤. 맥북에서 운영 DB를 직접 건드리지 않음

## 6. 데이터 소스와 처리 규칙

| 소스 | 설명 | 처리 규칙 |
|---|---|---|
| journal | 모닝페이지, 매일 타이핑, 날짜별 MD | 문단 단위 청킹, 채움 문장 필터, 14일 지연 규칙 |

| en-docs | 영어 기술 문서 | 제목 계층 기준 청킹, language=en, 오늘의 연결 후보에서 기본 제외 |
| research | 에이전트 생성 결과(inbox) | agent-generated 라벨, 승인 전 다른 모드 검색에서 제외, 승인 시 study로 편입 |

## 7. 데이터 모델(초안)

- **entries**: id, file_path, original_path, source_type, language(ko/en), sensitivity(private/semi/public), date, date_confidence(high/low), content_hash, imported_at, approved(research용)
- **chunks**: id, entry_id, idx, text, heading_path, embedding(raw), is_filler, excluded(사용자 영구 제외)
- **abstractions**: chunk_id, abstract_text(소스 중립적 추상 요약 1~2문장), embedding(abstract)
- **derived**: chunk_id, themes, emotions, imagery, seeds, entities
- **glossary**: id, term, context_sentence, source_chunk_id, seen_count, last_seen
- **resurfacing_log**: id, shown_at, anchor_chunk_id, surfaced_chunk_ids, condition, explanation_shown
- **feedback**: resurfacing_id, reaction, followup_entry_id(덧붙여 쓴 글), created_at
- **weekly_review**: week, kept_resurfacing_ids
- **jobs**: id, type, status(queued/running/done/failed), input, output_path, error, created_at, finished_at
- 보안: journal 관련 행은 별도 스키마(private)에 저장. 상세는 12장.

## 8. 가져오기와 파일 정리 파이프라인

**원칙**: 원본은 수정하거나 이동하지 않습니다. AI는 제안만 하고 사람이 승인합니다. 원본 경로와 정리 경로의 매핑을 기록해 되돌릴 수 있게 합니다.

1. 인벤토리: 형식, 개수, 용량, 인코딩, 날짜 정보 집계
2. 정규화: UTF-8 통일, txt → md, frontmatter 최소 필드(date, source_type, tags) 보강. 날짜가 없으면 파일 수정일 사용 후 date_confidence=low
3. 중복 탐지: 해시 기반 완전 중복, 임베딩 기반 유사 중복은 후보로만 제시
4. 분류 제안: 로컬 LLM이 source_type과 태그 제안, 사용자 일괄 승인
5. 민감도 라벨링: 규칙(폴더, 키워드)과 LLM 판정 병행, 불확실하면 private
6. 개인정보 패턴 검사(계정, 금융정보, 타인 연락처 등) 후 경고

시간 상한: 정리 작업은 전체 일정의 약 20%를 넘기지 않습니다.

## 9. 모드 1(오늘의 연결) 설계

### 9-1. 검색 레이어
- 같은 소스 내 검색: 원문 임베딩
- 교차 소스 검색: 추상 레이어 임베딩. 근거: 문체와 장르가 다른 글은 원문 임베딩에서 장르끼리 뭉치는 경향이 예상되고, 의미 있는 교차 연결은 주제 유사보다 구조적 유추인 경우가 많기 때문(가설, 검증 필요)
- 유사도 절대값 대신 소스 쌍별 순위(백분위)로 정규화
- 허브 보정: 자주 노출된 문단은 감점

### 9-2. 실험 조건(무작위성 다이얼)
무작위는 대조군이 아니라 정당한 실험 조건 중 하나로 봅니다.
- 조건 A: 유사도 상위(뻔한 연결)
- 조건 B: 유사도 중간 순위대
- 조건 C: 후보 풀 내 완전 랜덤(통제된 우연)
- 조건 D: 추상 레이어 기반 교차 소스 연결
- 후보 풀 제외: 채움 문단, 사용자 제외 문단, 14일 미경과 journal, 미승인 research, en-docs
- 사용자에게 조건은 보이지 않고 로그에만 기록(블라인드)

### 9-3. 보여주는 방식
- 원문 문단을 먼저 보여주고, LLM 설명은 기본 숨김
- 설명이 필요할 때도 단정이 아닌 질문 형태("이 둘은 어떻게 이어질까요?")
- 근거: 8B급 모델은 아무 두 문단이든 그럴듯한 연결 이유를 만들어낼 수 있어 판단을 흐릴 수 있음

### 9-4. 안전장치(필수)
- "지금은 보고 싶지 않음" 버튼
- 특정 글이나 문단의 영구 제외
- 하루 노출 개수 상한(1~3개), 놓쳐도 쌓이지 않음

## 10. 평가 설계(탐색적 실험)

- **즉시 반응(한 번의 탭)**: 이미 알던 것 / 억지 같음 / 몰랐는데 납득됨 / 뭔가 쓰고 싶어짐 / 지금은 보고 싶지 않음
- **행동 신호(핵심 지표)**: 연결을 본 뒤 덧붙여 쓴 글이 생겼는가, 새 메모나 아이디어가 나왔는가, 북마크
- **지연 평가**: 주 1회 지난주 연결 목록을 자동 정리해 두고, 원할 때만 열어 "아직 남아 있는 것"을 고름. 알림이나 의무 없음
- **설명 품질**: "연결 이유가 억지였음" 별도 기록
- **한계**: 표본 1명, 4주 기준 약 80개 노출, 조건당 약 20개로 통계적 일반화 불가. 방향 읽기와 사례 수집이 목적. 신기함 효과를 고려해 최소 4주 이상 운영
- **결과 해석**: "랜덤도 비슷하게 좋았다"도 유효한 발견. 그 경우 시스템의 역할은 똑똑한 선택보다 좋은 후보 풀 구성과 보여주는 방식이라는 결론으로 문서화

## 11. 노트 내 조사 작업(부가 기능)

- 범위: 웹 검색 없음. 맥미니 로컬 MD(memo, study, 승인된 research) 안에서만 조사
- 구현: 에이전트 루프가 아니라 고정 워크플로 + 작업 큐(8B급 로컬 모델에서 더 안정적이라는 판단, 검증 필요)
  1. 질문을 여러 검색어로 확장(로컬 LLM)
  2. 검색어별 DB 검색, 결과 병합과 중복 제거
  3. 출처와 함께 정리(Qwen3.5-9B), 출처 없는 주장 금지
  4. `inbox/research/날짜-주제.md`로 저장(agent-generated, approved=false)
  5. 완료 알림
- 입구: 웹 화면, 직접 만든 텔레그램 봇, 또는 하네스(선택)
- 메신저로는 완료 알림과 개요만 전송. 본문은 Tailscale을 통해 로컬 웹 화면에서 확인(메신저가 외부 서버를 거치기 때문)

## 12. 보안과 프라이버시 경계

**원칙**: MD에 적은 규칙은 LLM에 대한 부탁이고, 권한 설정과 코드가 강제다.

- 디스크: FileVault 활성화
- 동기화: 일기와 개인 노트는 비공개 GitHub 레포(옵시디언 볼트)로 맥북과 맥미니 사이를 동기화한다. iCloud 같은 다른 클라우드 동기화 폴더에는 두지 않는다. 비공개 레포도 외부 서버에 저장된다는 점은 감수한 결정이며(2026-11-13), GitHub 계정은 2단계 인증으로 보호한다
- 공개 레포 차단: 앱 레포는 공개이므로 볼트를 앱 레포 밖에 두고, 커밋 전 검사(`scripts/privacy_guard.py`)와 CI 재검사로 일기 파일, 일기 표시 노트, 개인 경로의 커밋을 막는다
- DB 분리: journal 데이터는 private 스키마에 저장. MCP 서버와 조사 작업용 DB 계정에는 private 스키마 권한 미부여(Postgres GRANT로 강제)
- 소스 필터는 서버 코드에 고정. LLM이 넘기는 파라미터로 받지 않음
- MCP 도구는 읽기 전용 검색만 제공(문단 + 출처 반환). 파일 열기 도구는 가급적 제공하지 않음. 제공 시 실제 절대 경로로 변환 후 허용 폴더 검사(심볼릭 링크, `../` 우회 차단)
- 하네스는 별도 macOS 사용자 계정으로 실행하고, 일기 폴더는 해당 계정이 읽을 수 없도록 OS 파일 권한 설정. 하네스 내장 파일/셸 도구는 끄거나 작업 폴더 제한
- 메신저: 허용 계정 목록 필수, 주기적 자동 동작은 신뢰 확보 전까지 끔
- 로그에 본문 기록 금지
- 데모 모드: 데모 DB와 실사용 DB를 물리적으로 분리하고 환경변수로 전환. 데모는 공개 가능한 study 노트, 라이선스가 명확한 오픈소스 문서, 합성 일기 데이터로 구성
- Git: 앱 레포는 공개(2026-11-12 전환). 개인 기록(옵시디언 볼트)은 앱 저장소 밖의 별도 비공개 레포에 둠. `.env`와 비밀값 커밋 금지, `.env.example`만 커밋. 실제 볼트 이름과 경로는 공개 레포에 적지 않고 기기별 로컬 파일(`.private-patterns`, git 무시 대상)에만 둠
- 기기 분리: 개인 기록(볼트)은 맥북과 맥미니 양쪽에 있음. 앱이 개인 기록을 인덱싱하는 곳은 맥미니뿐이고, 맥북에서 개발할 때 앱은 demo-data만 사용. 공개 레포로 새는 경로는 커밋 전 검사와 CI 재검사로 막음
- 네트워크: Lemonade와 앱 서버는 Tailscale 망에서만 접근 허용. 공유기 포트포워딩이나 같은 와이파이 전체 공개 금지

## 16. 포트폴리오 가치 자체 평가(검증 대상)

**강점**
- 하나의 공통 엔진 위에 목적이 다른 모드를 얹은 확장 구조
- "앱(MCP 서버)과 그 앱을 쓰는 에이전트(미니 하네스)를 둘 다 직접 만들었다"는 이야기
- 무작위성을 설계된 변수로 다룬 탐색적 실험과 정직한 결과 보고
- 권한 경계를 프롬프트가 아니라 DB 권한, 코드, OS 계정으로 강제한 보안 설계
- 미술 전공 + 개발자라는 서사와 "직관과 영감"이라는 주제의 연결
- 모닝페이지 데이터와 분리된 공개 데모 구성

**약점과 리스크**
- 단일 사용자 앱이라 협업, 확장성, 운영 신호가 약함(테스트, CI, 문서화, 작업 큐로 보완)
- RAG 앱은 흔함. 평가와 설계 결정 기록이 없으면 묻힐 수 있음
- 범위가 넓어 "전부 반쯤 만든 상태"로 끝날 위험. 모드 2, 3과 평가 문서 완성이 최우선
- 8B급 로컬 모델의 한국어 구조화 추출과 도구 호출 안정성
- 목표 포지션(일반 풀스택 / AI 엔지니어링)에 따라 강조점이 달라짐

## 17. 주요 리스크와 대응

- 임베딩 서버 구성 실패 → llama-server 분리 운영
- 교차 소스 연결 품질 낮음 → 추상 레이어 프롬프트 개선, 리랭커 도입, 조건 비교 결과로 판단
- 사용 지속 실패 → 입구 단순화, 압박 요소 배제, 놓쳐도 쌓이지 않는 구조
- 과거 기록이 예고 없이 돌아와 아픔 → 건너뛰기와 영구 제외 필수
- 에이전트 결과물의 환각이 노트를 오염 → inbox 격리와 승인 후 편입
- 경계 우회(일기 노출) → DB 스키마 권한, 코드 고정 필터, OS 계정 분리의 3중 경계
- 개인 기록이 Git에 커밋됨 → 기록 폴더를 저장소 밖에 두기, .gitignore, 커밋 전 검사
- 범위 팽창 → 비목표 목록, 동시 진행 2개 제한, 아이디어 목록
